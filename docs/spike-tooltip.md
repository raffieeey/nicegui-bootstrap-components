# Tooltip strategy

The library renders Tooltip as a Vue component, not as a `bootstrap.Tooltip` JavaScript Plug attached to the target node. The overlay contract already requires a portal into `#ngbs-overlay-root` (classes `ngbs ngbs-overlay`, `data-bs-theme`, Mode B stacking context). A Plug instance defaults to `container: 'body'`, which escapes that root, misses scoped `--bs-*` variables, and sits in the wrong stacking context relative to Modal, Dropdown, and Toast. NiceGUI 3.17.1 may remount an element when listeners are registered after first render, and `ui.refreshable` tears down browser plugin state; a Bootstrap instance bound to the target then leaks a hidden tooltip node and native listeners unless every remount path calls `dispose()`. A V tooltip owned by `OverlayElement` follows the same desired-versus-actual `is_open` path as Modal and can treat the target as a reference rather than as the host of foreign JS state.

Cleanup is deterministic. On Tooltip unmount, or when the target is deleted, the Vue instance stops Floating UI `autoUpdate`, clears show/hide delay timers, removes the portaled `.tooltip` node from the overlay root, and drops resize, scroll, focus, and hover listeners. The target is not left with Bootstrap data keys. Hide is best-effort if the target is already gone; leftover `.tooltip` or `.tooltip-inner` under `#ngbs-overlay-root` is a failure.

The browser suite does not yet run the 8.5.13 listener-leak probe; the demo app still constructs a `bs.Tooltip` so the V module loads next to Modal and Toast. The suite does assert that `import('vue')` resolves to the host `/_nicegui/` `vue.esm-browser` runtime (the V path must not bundle Vue) and that a dark-mode stub can write `data-bs-theme` on the overlay root while a modal is open — the same portal Tooltip will use. Residual risks are trigger and delay parity with DBC (`hover focus click`, dict delays), focus-plus-hover accessibility, and accidental double-initialization if `bootstrap.bundle.min.js` also auto-inits `[data-bs-toggle=tooltip]`. Library markup must not include that attribute. If V positioning slips in a later release, the fallback is still a Plug with `container: '#ngbs-overlay-root'` and explicit `dispose()` on the NiceGUI delete hook, not a third implementation.
